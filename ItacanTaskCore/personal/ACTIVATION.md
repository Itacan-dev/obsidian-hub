# Activation review: stationary computer and laptop

This is the preserved v1 procedure. A future activation of the staged v2 candidate must use [ACTIVATION-V2.md](ACTIVATION-V2.md), including direct v2 enrollment and explicit profile confirmation.

**Not executed.** Ordinary Work has no personal activation, space or published evidence. This is a forward procedure for a separate explicitly authorized operation. There is no end-user enable toggle or automatic enrollment on import.

1. Review the unresolved limitations in README, particularly read-only conflicts, finite history capacity, key loss and background synchronization latency. Generate an exact-hash compatible-client package from the final staged candidate; the installed repaired build and its previous package do not implement this capability. Upgrade both clients while personal synchronization remains disabled. Retain rollback assets. Do not change the two Git Project bindings or genesis.
2. Close ordinary writers normally on both devices. Back up all local native repositories, retained requests, activation/configuration, protected keys if any, and local application data to verified device-private nonsynchronized storage. Never copy one device's identity or live repositories to the other. Revalidate authority IDs, partitions, owner roots, current heads, recovery fences and unresolved requests. Stop for substantive inconsistency. Recount current data rather than assuming the eight-task baseline remains current.
3. Confirm both vault registrations and physical Resource ownership. Ensure `.itacan-personal-sync` is untracked and effectively ignored at the vault Git root. Stop if tracked; do not delete/untrack it automatically. Verify ordinary paths contain no escaping symlink/junction. The transport repeats these checks before publication.
4. Create each device's distinct replica UUID/key using `personal/local-identity.createIdentity(file, safeStorage)` in its local PersonalSync key directory. No plaintext fallback. Exchange public keys and the complete binding fingerprint through a channel the user can compare. Create one space UUID on the stationary device; it is the initial enrollment publisher, not a permanent runtime primary.
5. Under writer quiescence, prepare nine seeds using `enrollment.prepare({spaceId,state,capability,signer})` from current authoritative states, with the exact current capability. Preserve every source identity, tombstone, receipt and native event. Build one binding with nine physical owner mappings and their seed digests. Use `binding.validate`, `fingerprint`, `confirm`, `enrollment.validate` and `membership.certify`. Keep these preparations outside OneDrive until review. Do not put the 182 Legacy History rows or application data in seeds.
6. Prepare owner-specific local activation records. The loader `lib/services/native-personal-activation.js` defines the exact record: sealed `itacan-personal-local-activation` v1 with vault/device/owner/authority, binding/seed/members/fingerprint, protected key path, and existing host options. Store beneath `%LOCALAPPDATA%/Itacan/PersonalSync/v1/<registration-hash>/owners/<owner-key>/ACTIVATION-v1.json`, using `base()` and the existing activation `seal()`/ownerKey helpers. Source options use `personalEnrollment:"source"`; assign one fixed `personalEnrollmentOperationId` per owner. Preserve the source repository directory, authority and private partition. Do not invent a Git shareApproval.
7. Recheck source heads and physical/inventory evidence immediately before admitted `personal.enroll`. Startup/runtime admission uses the existing writer path. The capability barrier prevents old clients from reopening earlier generations. Verify preserved logical state and source receipt prefix, then permit immutable publication. If enrollment loses acknowledgement, use Native task recovery to inspect/reconcile or explicitly review exact replay, then Reopen personal authority. Do not change IDs or erase requests/fences.
8. Let OneDrive carry bindings, seeds, member certificates and proof dependencies. On the laptop, validate the independently compared fingerprint and original seeds before local initialization. Configure **join** activation using its own vault registration, device binding, replica key, local directory and fixed bootstrap operation ID; use the original logical authorities and space. The reviewed join directory must be empty. `personal.bootstrap` produces the laptop's own local application receipt and consumes the existing genesis/seed, never a second genesis. Wait for absent referenced notes/folders; do not relocate them.
9. Before enabling routine background use, compare the complete logical owner/task/Step/event/tombstone identities and properties across both devices. At this session's baseline, this is eight live private tasks and 17 outstanding Steps, including the original Pulsed task. Verify local Legacy History independently (182 rows on the stationary baseline), with no import into personal events. Existing Git tasks must remain on their existing N4 namespaces.
10. Verify representative bidirectional edits, native completion/reopening only on legitimate tasks, explicit conflicts, restart and normal shutdown on both devices. Confirm writer release and no duplicate events. Inspect status: locally published is not cloud availability, and peer acknowledged requires validated receiving evidence. Enable normal background synchronization only after that review.

## Rollback and forward recovery

Before any enrollment commit, private unpublished preparation may be abandoned without changing existing repositories. After enrollment but before publication, pause; there is no automatic downgrade/unenroll tool. Any reversal requires a separate explicit, quiescent review of exact repository and retained evidence.

**First publication is the external rollback boundary.** Once another device may have consumed evidence, restoring an old snapshot is not a safe rollback. Preserve space/authority/replica identities and immutable records. Recover forward using original receipts and retained operation IDs; re-export committed unpublished origins, wait/retry incomplete delivery, or inspect/reconcile uncertain native writes. Do not rewrite immutable objects, remove conflicts, reset fences, force-release writers, create another seed/genesis or restore a stale snapshot over accepted work. Key loss, required revocation and unresolved conflicts require explicit follow-up; no improvised writable resolver is provided.
