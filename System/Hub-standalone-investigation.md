# Standalone Itacan — first build decision

**27 November 2026 · Internal product and engineering review**

**Recommendation: approve one offline research workflow.** A researcher chooses a library, opens a Project from Home, browses a folder, edits a Markdown note, creates a task in that note, and completes it from Home. They quit, move the library, and recover the note, task and working layout on a fresh profile. A shared Resource folder should open the same note from either context. If these actions feel like Hub and the files survive independently of the installation, the team has a recognizable running prototype.

There is a head start. Commit `bd86f07c9729b63d393a16b6bcf31537832fdb04` on `itacan-second-strike` in `Itacan-dev/obsidian-hub` includes standalone Itacan 0.2.0. Its library, editor buffers, local transactions and desktop test are credible starting points. Its UI, source editor and task storage still differ from the design. The checkout had pre-existing working-tree deletions throughout `Itacan/`. I inspected that version from Git and used a temporary extraction for tests. The proposed implementation branch is `standalone/research-prototype`, based on that commit in a separate checkout. Creating it is part of a future implementation decision.

## A portable library and the smallest task that works

**Source.** Hub today gives a task a stable ID in a device-local SQLite database, with a Project/Resource owner and optional note or folder context. Its UI reads committed rows. A task can exist at the workspace root without any Markdown checkbox. The database path is derived from the absolute vault path. Closing and reopening the same vault reconnects to it. Moving the entire vault changes the key, so copying the vault alone can strand tasks and their history. An in-app file move is different: Hub durably prepares the rename, changes the filesystem, and updates affected task contexts, including completed tasks. External renames bypass that coordinated command. The September report describes an earlier Markdown checkbox + `hub-task` comment + metadata design. `Core/host/storage.cjs` · `workspaceIdentity`, `storageLocation`; `Core/schema.sql`; `Hub/lib/services/native-task-host.js` · `createNativeTaskHost`; `System/Hub-files-explorer-stage2.md` · Durable coordination and recovery; `System/Hub-task-planning.md` · Persistence and source safety.

**Recommendation.** Let a source note own its tasks. Store a readable Markdown checkbox and optional nested Step checkboxes. On creation in Itacan, add a stable UUID and optional small, versioned metadata in a hidden Markdown comment on the parent line. Text and check state have exactly one editable home. Metadata carries explicit Necessity, optional From, Until, Due and Planned, and completion time when known. A dated deadline is independent of importance. From controls availability, Until closes an opportunity and leaves it available for review, Due orders overdue then upcoming work, Planned records intended work. Within equal deadlines order Must, Should, To do, then source order. A future task keeps its badge. Defer recurrence rules until the capture/complete loop works.

A proposed on-disk example is below. The parent alone is scheduled. Its location is the actual note containing the ID.

```markdown
- [ ] Check canopy measurements <!-- itacan-task {"v":1,"id":"69b89aca-abab-4371-bb0f-20fc1a9207c6","necessity":"should","due":"2026-12-02"} -->
  - [x] Read field log
  - [ ] Compare repeat samples
```

An ordinary external checkbox can be identified provisionally by its note and block. Assign an ID when the user first needs a durable reference or edits it through Itacan. Locate by ID after opening or rescanning, with the line number as a hint. A renamed or moved note carries its tasks even outside the app. A copied folder containing the same ID surfaces a duplicate for resolution. In-app duplication gives copied tasks fresh IDs and leaves existing Plan/Oath references at the original. Keep missing references visible with their last known labels. Offer relinking when two copies could be the source. Keep completed items in History even if the original is eventually removed. Prevent silently removing an unfinished bound task during an active task-based Oath.

**What needs to survive a crash.** For a **note edit**, two panes share one buffer and its last-read revision. Save/short idle autosave sends a relative path, expected revision and bytes to main. Main validates the library root and file, preserves encoding/newlines, writes and flushes a same-directory temporary file, checks for external changes, replaces the original, and acknowledges the new revision. Keep the draft on failure or conflict and offer reload or save a copy. Drain pending edits before switching library or quitting.

For a **task completion**, use the same note buffer so a Home click cannot overwrite a researcher's draft. Resolve the task ID, request the desired state (`done=true`), and validate the current source. Persist a short local pending change identifying the task, expected revision, desired checkbox edit and history event ID. Save the note, then atomically record the completion in portable work data, evaluate any active task-based Oath, and clear the pending entry. Refresh Plan, History and the task rows after commit. A replay checks the ID and existing event before acting. If the note changed incompatibly, retain both versions for review. Reopening reverses current state and updates history accounting without double-counting. Finishing a Step alone never fulfils an Oath. This small recovery record serves a single-user need: a note and its history are separate files. Use the same prepare/reconcile pattern for a move that also changes saved layout or media references.

Use root-relative paths for files and stable workspace/task IDs for associations. Named presets, logical split ratios, sorting, user shortcuts, chosen colors, relative artwork, Plan day/time zone and Oath history travel. Resolve OS shortcut modifiers on the new device and flag conflicts. Keep absolute window positions, notification permissions, vetted executable paths, Strict opt-in and active window ownership local. **Ambiguous:** Last File and rail widths are personal working context but may feel wrong on a smaller computer. Recommend carrying the logical desk and width preference, clamping to the new window. Carry shortcut labels, allowlist intentions and music ordering, and ask for fresh device bindings. An unfinished Oath travels as a record. On a fresh device show reconciliation before any new commitment, with local permissions and window state initially inactive.

For a path outside the root, offer **Copy into library** or a clearly labelled **device-only reference**. A moved installation can show its last label and offer Locate or Remove. Check resolved targets, including symlinks/junctions, before a read or write. Never silently follow an external path found in Markdown or import its target. Preserve externally authored links as text. Offer relinking for broken relative embeds and saved paths after external reorganization. For files without a task anchor, request a selection when identity is ambiguous. The portability promise applies to local, fully available files and one closed writer at a time. A sync provider handles transport. If it delivers conflicting copies, preserve them for user review.

## One architecture and explicit reuse decisions

```text
standalone/research-prototype                 Proposed branch in Itacan-dev/obsidian-hub
  Itacan/
    main/app.cjs, preload.cjs                  Window, lifecycle, validated desktop API
    main/library.cjs, files.cjs, work.cjs     Root selection, file operations, serialized JSON saves
    main/tasks.cjs, plan.cjs, oath.cjs        Note tasks, Plan/history and commitment rules
    main/platform/                            Later, capability-tested OS integrations
    renderer/home/, workspace/, document/     Feature composition and feature CSS
    renderer/tasks/, plan/, oath/, settings/  User-facing interactions and feature CSS
    renderer/ui/                              Tokens, buttons, cards, dialogs, tree, splitters
    assets/, examples/, test/                 Bundled assets, synthetic library, regression checks
```

Build on the existing JavaScript/Electron modules. Main selects a library, performs asynchronous file IO, owns the save queue and active Oath, and restores native windows. Preload exposes named operations such as read note, save note, set task completed and open preset. Validate the calling window, inputs and library-relative target in main. The sandboxed, context-isolated renderer owns presentation, editor state and keyboard focus. Give it safe local attachment URLs and no arbitrary filesystem, shell or IPC facility. Render Markdown with raw HTML disabled and keep content inert. Designers edit feature markup/CSS, artwork and shared UI tokens in the renderer. Platform code belongs behind narrow operations such as picking a folder, trashing a file or discovering permitted apps. [Electron security guidance](https://www.electronjs.org/docs/latest/tutorial/security)

## Oaths, Firefox, music and Athena

**Regular Oath.** The detailed feature design calls for a ceremonial pledge, one or more real tasks and exactly one fulfilment condition. A duration expires automatically. “Until ended” asks whether the work was done. “Until selected tasks are complete” finishes on the final required parent task. For indefinite and task-based sessions the design offers a 1–60 minute break, automatic resumption and Resume now. For inactivity it proposes a quiet prompt, with 5 minutes outside Note view and 10 or 30 minutes inside. Confirmed thinking or paper work keeps its time. The AFK deduction and optional camera behavior remain design work. Persist the start/schedule, condition, selected IDs, breaks, elapsed time and terminal outcome. Capture a terminal record once before releasing the normal fullscreen guard. Give storage failure a visible recovery path. `Meta/The Oath Functionality.md` · Agreed functionality; `Hub/lib/services/oath.js` · `persist`, `end`, `#finish`.

**Strict Oath.** Preserve explicit device opt-in, preflight, review of a frozen permitted-app list, separate acknowledgment and refusal of ordinary early exit. A permitted app may be above the fullscreen Itacan window. Keep the dock/return action and a recoverable window-state snapshot. The current Windows prototype's version-4 reminder appears after about three observed seconds in a known non-permitted foreground app and hides on return. Unknown or stale observations can miss it. It does not seize focus. Earlier bounded focus nudges describe version 3. Prototype recovery uses a separate window, a *local* Ctrl+Alt+Shift+F12 and a two-minute watchdog. A fresh Strict process reconciles an interrupted Oath once and starts with guards released. Preserve retry of window restoration; keep test release mechanisms explicitly scoped to internal builds. `Projects/Itacan/PLAN.md` · Centered Oath Reminder prototype; `Hub/lib/domain/oath-strict.js` · `STRICT_TERMS`; `Hub/lib/services/oath.js` · `recoverStrict`; `System/Hub-oath-phase5.md` · Delivered recovery behavior; `System/Hub-oath-prototype-recovery.md` · Strict Oath prototype installation.

## Decisions for product and design

The following choices affect what someone sees. The proposed defaults allow unaffected investigation and engineering to proceed.

| Choose when | Practical difference and question |
|---|---|
| **First build · Resource name** | `Meta/Functionality.md` · Resources says **Literature**. `Meta/Design.md` · Icons says **Research**. `Hub/lib/config.js` · `RESOURCE_TYPES` displays the latter with a legacy ID and old-root aliases. **Which label and default folder name should the publication Resource use?** Keep one stable identity through a future rename. The demonstration can use Knowledge. |
| **First build · Full view** | `Meta/Functionality.md` · Folders and subfolders gives each Workspace Folder its own panel. The subsequently accepted Hub explorer uses one resizable tree/details panel with single-click selection and double-click opening. These allocate the primary working area differently. **Should the standalone reproduce the per-folder panels or adopt the later explorer?** Recommend the written per-folder composition pending an explicit design amendment. Keep one file-operation layer for either choice. `System/Hub-files-explorer-stage1.md` · Stage 1 behavior; `Hub/lib/ui/workspace-explorer.js` · `mountWorkspaceExplorer`. |
| **First build · source of a captured task** | The task feature design's *Task structure* describes a task in a source note. Hub and 0.2.0 also support workspace/folder-only tasks (`Core/application.cjs` · `validateValues`; `Itacan/main/tasks.cjs` · `saveTask`). **When captured from Home without choosing a note, may Itacan use a visible Tasks note in a designated capture folder, or must the task be allowed to remain unattached?** Recommend the note. Selecting a destination later can move the same task ID. This choice changes the minimum storage model. |
| **First build · row presentation** | Numeric importance in `Meta/Functionality.md` · Tasks to Do conflicts with the task feature design · Necessity appearance. | **Plan phase · Home's middle panel** | `Meta/Functionality.md` · Today's Focus describes editable daily text. `System/Dashboards/Home/view.js` · Today's Focus displays Plan; `Hub/lib/ui/plan.js` · `legacySources` can recover earlier Focus items. **Can the daily Plan note carry Today's Focus in that same panel, or is a distinct editable Focus required?** Recommend one panel with a short focus note and optional ordered entries. |
| **Oath phase · fulfilment, timing and history** | The detailed Oath design · Fulfilment conditions, Scheduling and Oath history gives mutually exclusive end conditions, a cancellation boundary at the start of the scheduled *day*, and a fourth History tab. Hub requires selected tasks plus a duration, latches the first of timeout/all complete, and allows continuing Oathbound after fulfilment. `end` also permits scheduled cancellation up to activation in ordinary cases. Home renders three History tabs. **Should the standalone use explicit end conditions, the day boundary and an Oaths tab as designed? Should continuing after fulfilment start a new session?** Recommend the feature design and a separate new commitment. `Hub/lib/domain/oath.js` · `oathRequirements`, `fulfilmentTime`; `Hub/lib/services/oath.js` · `end`; Home · `renderActiveProgressView`. Both architecture documents · Strict Oath architecture call a restart **broken**; `Hub/lib/services/oath.js` · `recoverStrict` records **interrupted**. **May unsupported platforms offer an accurately labelled in-app Regular commitment, with Strict unavailable there? Should interruption have its own History status and count separately from an explicit Break?** Recommend yes to both, retaining explicit Break for Regular and independent emergency recovery for Strict. Site enforcement inside permitted Firefox is already resolved. |

For later design review, choose whether an unfinished Step needs confirmation on parent completion, how future/expired tasks are revealed, and whether Planned affects the main list. Default to parent-controlled completion, a collapsed future section and Due ordering. Before indefinite/scheduled Oaths ship, choose restrictions during rest, removal of selected work, already-finished scheduled tasks and the idle deduction.
