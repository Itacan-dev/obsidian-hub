# Itacan standalone application — architecture and development decision

**27 November 2026 · Internal product, design and engineering review**

**Foundation decision: yes, with substantial refactoring.** Keep the working Electron application. A researcher can already organize a Project, write a note in two panes, make a daily Plan, report progress and reopen their work offline. Recreating that foundation would spend time rebuilding behavior that has executable tests. Extending it unchanged would make Markdown-only routing, a generic state-update command and incomplete handling of moved files the foundation for every new feature.

**Implementation contract for the integrated development run.** Its outcome is a daily-use application in which a researcher can collect material, work across Projects and Resources, read and write in one desk, capture and plan work, take a Regular Oath, review evidence of progress, and carry the complete library to another computer. Organize the run around shared operations, document identity and portable state. PDF viewing is one client of that architecture. Keep the application runnable at each checkpoint. Internal use and polish precede distribution to selected testers.

For the team review, start with the [capability matrix](#capability-matrix), the [development program](#one-development-program) and its [acceptance demonstration](#strong-internal-build--acceptance-demonstration). The [product questions](#product-discrepancies-for-the-team-review) and [final recommendations](#final-approval-recommendations) collect the decisions. For implementation detail, see the [portable data model](#portable-state-ownership-and-recovery), [five operations](#five-operations-from-interaction-to-disk) and [editor decision](#documents-editing-and-the-working-desk).

## The working day and the decisions it exposes

1. **Choose the library and orient at Home.** **Established from source.** On first launch the shell shows the chooser. An empty directory gains a versioned marker and standard workspace roots. An unrelated populated directory is rejected. Launch reopens the device’s last path or asks to reconnect if it moved. Switching through the library name passes the dirty-document guard. Home shows the greeting, local agenda, daily Plan, Tasks, Project status groups, Resource cards, Progress and capture controls. Empty Projects and tasks have an established region. **Inferred.** Keep this as the first screen, with one sentence explaining what travels with the folder. Show any active commitment in a persistent footer on Home, Full view and Note view. [Library selection and session](../main/app.cjs) · [Library initialization](../main/library.cjs) · [Home composition](../renderer/home/home.js)
2. **Open a Project and bring a Resource into context.** **Established from source.** New Project creates a real directory, status and order live in work metadata. The card opens its last browsed folder. Full view combines the tree and file listing with workspace Tasks and Progress. A note opens the desk with a contextual rail. The current app creates four Resource directories and also enumerates any additional directory in the collection. The design gives Projects access to folders owned by Resources. **Inferred.** Attach a Resource folder to a Project by relative reference. Opening it retains the Project rail and shows the physical breadcrumb. Editing changes the original file. Home counts a task once. Detach removes only the attachment. Keep an unexpected Resource folder accessible for recovery without promoting it into a fifth fixed category. See `M/Functionality.md`, “Shared Resource folders”, `H/lib/config.js` (`RESOURCE_TYPES`), `A/main/library.cjs` (`home`) and `A/renderer/workspace/workspace.js` (`workspaceView`).
3. **Research at a desk.** **Established from source.** The browser, note rail, search, Plan and Markdown links can open content, but each entry point makes its own note/attachment decision. PDFs and standalone images leave the desk through `shell.openPath`. Read mode already supports TeX and local embedded images. Editors in two panes share a draft. **Inferred.** All five entry points should request the same document operation and carry both the physical path and the working context. Opening a paper beside a note, moving its tab and restoring the desk should preserve the same context. See `A/renderer/app.js` (`ctx.openNote`, `navigate`), `A/renderer/ui/context-search.js` (`contextSearch`), `A/main/app.cjs` (`open-attachment` handler).
4. **Capture a thought and plan work.** **Established from source.** Quick Add keeps a text draft or stages files, Inbox resolves items to a destination, and failed filing can leave them available. Tasks can be created directly from Home/workspace or from captures. A daily Plan selects existing tasks, files and workspaces. Project planning in Hub separately maintains dated phases and milestones. **Inferred.** Keep a single daily Plan across workspaces and a Project-owned roadmap. In Full view expose the current Project’s Plan entries and an action to add work without creating a second daily Plan. Preserve Quick Add’s immediate submission and draft protection. See `A/main/files.cjs` (`fileText`, `resolveAttachment`), `A/main/work.cjs` (`command`), `A/main/plan.cjs` (`planAction`) and `H/lib/domain/project-planning.js` (`planningState`, `roadmapViewport`).
5. **Commit, record, resume.** **Established from source.** Hub has a shell Oath and separate native experiments. The standalone already has authored progress reports, history, statistics, Last File and named presets. **Inferred.** During an Oath the same task checkbox remains authoritative. On ending a session its outcome belongs in History. When closing after work, allow the researcher to report a rating/reflection or leave. Tomorrow, Home resumes the global last desk, while a workspace resumes its own last desk. This joins four systems without making a timer or a daily score the organizing principle. See `M/Functionality.md`, “Last File” and “History”, `H/lib/services/oath.js`, `A/main/progress.cjs` and `A/renderer/app.js` (`onRequestClose`, `restore`).

## Runtime checks that change the plan

**Observed.** The installed executable was `Itacan/node_modules/electron/dist/electron.exe` on Windows 11 Pro x64, OS build 26300. It reported app 0.3.2, Electron 45.4.1, Chromium 156.0.8078.100 and embedded Node 24.22.3. The test CLI used Node 24.19.0. All eight authored main/preload files matched the built copies byte-for-byte. The repeated desktop suite passed with zero captured renderer HTTP(S) requests and zero page errors. No macOS or Linux device was exercised in this investigation.

| Disposable experiment | Result and implication |
|---|---|
| First use, relocation and recovery | Through the visible chooser with its native result supplied, an unrelated nonempty directory was rejected and its contents survived. An empty directory initialized. Through the real preload and main operations, a Project gained a saved note, completed task, Plan and preset. An in-app Project rename repaired the task, Plan and layout routes. Moving the closed library made the original profile offer reconnection. A fresh profile opening the moved root recovered the note text, task UUID and completion, Plan references and preset path. This checks durable state. The regular desktop suite separately exercises quit prompts. |
| External move | Renaming the note outside Itacan changed its directory listing. The old route failed to open, while the task, Plan and preset still stored the old route. Opening the new path returned the same bytes. A second filesystem-level fixture confirmed that a workspace-only task could be attached, completed and carried to a copied library. External rename needs visible repair, even though in-app moves work. |
| Editing continuity | Actual Ctrl+Z/Ctrl+Y worked in a mounted source editor. After switching tabs and returning, the unsaved text remained but Ctrl+Z no longer undid that insertion. A synthetic 897,000-byte, 3,000-section manuscript opened in reading view in 161 ms. A focus, caret move, single insertion and visible dirty-state check took 125 ms in source mode. Neither figure measures sustained typing or Live Preview. |
| Finding work | A synthetic Project with 1,000 Markdown notes of about 1.9 KB each took 1,335 ms from query entry to a unique text result and 832 ms to a filename result. These single measurements include the debounce and have uncontrolled cache order. They justify delivering filename matches before the content scan completes. They do not establish a need for a database. |
| Historical behavior fixtures on this host | 42 selected Hub/TaskCore cases passed from `H/lib/tests/global-plan.test.js`, `plan-lifecycle.test.js`, `progress-workflow.test.js`, `oath-preflight.test.cjs` and `C/tests/file-operations.test.cjs`. They exercise local-day boundaries, report conflicts, Break/interruption and managed file references with isolated state. They do not test desktop enforcement. |

**Unverified.** This run did not repeat the live Obsidian Oath walkthrough, activate real host restrictions, measure sustained third-party sync, conduct a user study, or establish fresh-installer behavior. The historical Hub observations and physical checks still outstanding are identified separately.

## Portable state, ownership and recovery

**Established from source.** `A/main/library.cjs` (`openLibrary`, `resolve`, `readNote`, `saveNote`) keeps ordinary content on disk. Its version-1 marker recognizes the library. `A/main/work.cjs` (`LibraryWork.load`, `transaction`) loads and serializes the work JSON, compares the original bytes before replacement and queues updates per library. The JSON contains authoritative user work as well as small presentation preferences. It is not a disposable cache. Only the path to the last library currently goes in the app profile’s settings. A task belongs to a workspace and may refer to a more specific path. Nothing in the note bytes is required to identify that task.

**Inferred — proposed disk layout.** Tasks, Plans, Oaths, workspaces, presets, progress and settings each own their rules and expose named operations. The storage module maps their records to `itacan-work.json` and owns serialization. Feature code consumes operation results and scoped reads. Keep one readable file unless measured workload or recovery needs justify a split. Task completion, Oath fulfilment and a history fact can then commit together. Store a logical workspace’s physical relative root, status and shared folder references in work metadata. Keep the lightweight marker as the format gate. Retain path-based identity for files, stable UUIDs for tasks/steps, Plan entries, sessions and records that can outlive their targets. A workspace rename through Itacan rewrites its route. The four fixed Resources are Knowledge, Literature, Explorations and Inspiration. New libraries use `Resources/Literature/`. In existing 0.3.2 libraries, display the legacy `Resources/Research/` folder as Literature and retain its physical path and references. If both folders exist, preserve both and flag the ambiguity during migration. A file does not need frontmatter to join a workspace.

```text
Field Library/                            selected and moved as one folder
  itacan-library.json                     format and supported library version
  itacan-work.json                        Tasks, Plans, Oaths, reports/events, workspaces,
                                          daily and project planning, presets, portable settings
  Projects/Forest survey/
    Field notes/Canopy.md
    Figures/canopy.jpg
  Resources/Knowledge/Methods/Sampling.pdf
  Resources/Literature/Papers/…
  Resources/Explorations/                 Resources/Inspiration/ is the fourth category
  Inbox attachments/                      staged native files referenced by capture IDs
  Media/                                  imported covers or optional library audio
  Trash/                                  fallback when native trash cannot accept an item
  .itacan-recovery/                       only when needed for an upgrade or pending file operation

Installed application/                    executable, renderer bundles, fonts, art and licenses
Electron userData/Itacan/                 device settings, window geometry, session/cache,
                                          optional local recovery drafts, diagnostic logs
OS credential storage/                    future authorized integration secrets
```

**Inferred — references and movement.** Store forward-slash paths relative to the library. Resolve them against the active library in main. Preserve actual spelling and filesystem identity. Never lowercase all paths or count two contexts on one shared folder as two notes. A directory link in Itacan is metadata pointing to an allowed Resource folder, not an OS symlink. Imported attachments become ordinary files inside the library. An explicitly configured external application, music source or website can have a display label. An external executable/file path is a device binding. On another device it requires Locate/Import or remains unavailable. Markdown absolute references should remain visible as authored, with an option to copy eligible assets into the library and insert a relative link. Reading a note must not silently fetch a remote image or grant access outside the root. Moves do not rewrite arbitrary hand-authored prose or guess at every Markdown link. Report affected relative media/links for review.

**Inferred — one writer and third-party sync.** Close before copying the whole library or switching machines, allow the host sync tool to finish, and make the folder available offline. On reopening, read current files and validate references. On wake/focus, recheck open documents and metadata revisions. Detect competing edits against the last acknowledged revision, keep the draft or incoming copy and expose a resolution action. A single-instance app lock protects one local app process. It cannot lock a cloud folder on another device. Avoid merge promises, peer identities, sync tokens or last-writer-wins overwrites.

## Proposed source and process boundaries

**Inferred.** Continue using ordinary JavaScript modules, feature-owned views and one local Electron main process. Add checked JSDoc/shared declarations at the preload boundary and for stored record versions. Keep the installed application self-contained under `Itacan/`. This tree describes destinations, not a demand to rename working files for symmetry.

```text
Itacan/
  main/
    app.cjs, preload.cjs                 lifecycle, IPC validation and narrow renderer bridge
    library.cjs, files.cjs, work.cjs     guarded paths, file operations and serialized metadata writes
    tasks.cjs, plan.cjs, progress.cjs    domain rules shared by all entry points
    oath.cjs, settings.cjs, search.cjs   commitment state, preferences and bounded reads
    platform/                           native launch/bindings, window restoration, optional Strict adapters
  contracts/                            operation signatures and persisted format declarations
  renderer/
    app.js, index.html                   shell, library session, navigation and command dispatch
    ui/                                 common controls, keyboard/focus behavior and shared.css
    home/, workspace/                   dashboard, Project/Resource full views, desk, rail, splits, presets
    document/                           buffers, source/live/read Markdown, PDF/image views
    capture/, tasks/, plan/, progress/   input, scheduling, Project roadmap, reports and statistics
    oath/, settings/, music/             feature composition and feature CSS
  assets/                               bundled artwork, icons and local media defaults
  scripts/, test/, examples/, docs/      builds, isolated checks, fixtures and design guidance
```

| Boundary | Responsibility and reason for changing it |
|---|---|
| Electron main | Own library selection and generation, native picker/trash, local content protocol, window lifecycle, Oath time/state, secure credentials if needed, and all durable operations. Keep `A/main/library.cjs` for path, UTF-8 and revision checks. Keep one serialized mutation per library. Separate domain actions from `LibraryWork.command` as each feature is touched. Give committed changes a monotonically increasing library revision so a stale UI response cannot replace newer state. |
| Preload | Preserve `contextBridge` and a named, typed surface. Gradually retire `update(session, group, action, data)` in `A/main/preload.cjs`. Expose operations such as `files.move`, `documents.read/save`, `tasks.create/attach/setCompleted`, `plans.save/finish`, `workspaces.attachFolder`, `presets.save`, `progress.saveReport`, `settings.setPreference`, mode-appropriate Oath operations, and `search.query/cancel`. Each validates its payload, session, caller and permitted scope in main. Return committed record/revision or a typed failure (missing, changed, unsupported, denied). Keep Electron events, arbitrary IPC channel names, shell arguments and Node out of page code. |
| Renderer | Own current route and workspace context, open documents, view selections/scroll, transient UI and accessibility. Make `openDocument` the common router. A menu, search result, task breadcrumb, Plan or later Athena action calls the same operations. Send intentional mutations through the existing session context. ### Five operations from interaction to disk

1. **Markdown edit and save.** The active editor dispatches a transaction to the document’s shared state. Other views apply the changes with their own mapped selections. **Current:** explicit Save sends the path, revision and text. Main preserves UTF-8 BOM and established LF/CRLF style, flushes a same-directory temp file and checks the old revision again before rename. Today `saveDocument` can roll back an already-written note if recording activity fails. **Proposed:** default to a short idle autosave (1 second since the last edit), retain explicit Save as an immediate flush and allow manual mode. Serialize per document, coalesce superseded drafts, mark only the acknowledged revision saved, flush on planned close/switch, and retain dirty text on error. Stop retries on conflict and offer compare/reload/save a copy. Once note bytes commit, report an activity-write failure separately. A statistics error must never reverse saved research text. `A/renderer/document/buffers.js`, `A/main/files.cjs` (`saveDocument`), `A/main/library.cjs` (`saveNote`, `atomicReplace`).
2. **Complete a task.** Home, the Note rail, Plan and Oath call `setCompleted(id, true)`. Main checks the current value, records the transition with its time, creates at most one recurrence successor and asks the Oath module to evaluate the applicable fulfilment rule. The storage module commits the resulting task, Oath and progress records in one work-file replacement. The active Plan resolves the same ID. A historical snapshot retains its recorded outcome. Publish the changed records after success. A retry after a lost acknowledgement is a no-op. A failed write leaves the old checkbox and available action. Restart reloads the same result. `A/main/tasks.cjs` (`toggleTask`), `A/main/work.cjs` (`transaction`), `A/main/progress.cjs` (`recordTaskChanges`).
3. **Move a note, folder or Project inside Itacan.** Validate origin/target and collisions, serialize against edits, capture the affected reference changes and expected revisions, and record a small pending operation before renaming. Update ownership, source paths, active Plan, Oath navigation, live history targets, explorer state, attached-folder links, tabs and presets together. Preserve historical labels/paths and remap open drafts to the new key. Confirm success after metadata commits. On restart, if only the recorded source or target exists and its identity/revisions agree, finish or undo the pending operation. If both, neither, or conflicting bytes exist, preserve both sides and show recovery. Current rollback closures only run in a live process. Use a recovery record for cross-file moves/filing, not a permanent event database for every edit. `A/main/files.cjs` (`moveItem`), `A/main/work.cjs` (`rewriteRefs`).
4. **Rename or replace outside Itacan.** Revalidate on open, window focus, before saving and on explicit Refresh. Directory-change notifications may trigger earlier checks but carry no identity guarantee. If an open clean file changed, reload it and preserve a clamped reading position. If dirty, retain the draft and show the conflict. A missing task attachment, shared folder, Plan entry or tab retains its last-known label/path. Offer Locate and update live references after the user selects the intended file. Keep a missing workspace’s tasks accessible from Home for reassignment. A replacement at the same path is the current file at that path. Never infer a rename from a matching basename or a copied file’s hash alone. The external-rename experiment above reproduced this ambiguity.
5. **Restore a preset.** Snapshot context, ordered tabs, active pane/tab, split tree and fractions, rail/folder state and per-document reading/editing positions. Resolve paths against this session. Load each valid document through its own viewer, restore position after layout, clamp obsolete coordinates and use a closable, relinkable placeholder for each missing item. Missing context falls back to the desk with its surviving tabs. Keep the saved preset intact until explicit Update. Guard any unsaved draft losing its last view. `A/renderer/app.js` (`ctx.restore`), `A/main/library.cjs` (`resolveLayout`), `A/renderer/workspace/desk.js`, `splits.js`, `presets.js`.

### Strong internal build — acceptance demonstration

1. Start offline in a clean profile. Create a library, create an Active Project, open Literature from Home, then browse Knowledge and attach its Methods folder. The Project rail stays in place while opening a shared paper.
2. Open a PDF, image and Markdown note in tabs. Split paper and note, select paper text, type a formula in Live Preview, embed a local image, switch to Read and return to the caret. Undo across a tab switch. Save a named desk with a particular PDF page and split proportion.
3. Use Quick Add without choosing a note. File the capture as a Project task, verify that its row has no classification badge, then attach it to the note. Mark two other tasks Should and Must. Search the library for a line of research text, open at the result, add the relevant note and task to today’s Plan and place a milestone on the Project roadmap.
4. Take a Regular task-based Oath. Complete a Step and verify the Oath remains active. Complete the last required parent and observe one fulfilled session. Take a second, timed Regular Oath and deliberately Break it. History distinguishes the outcomes. Log a workspace reflection and deliberate zero rating. Finish the Plan. Confirm report evidence and terminal labels after a later edit.
5. Change a shortcut and a cover. Move the note through Itacan and verify active task and preset routes. Externally edit the note while a dirty buffer exists. Resolve using a preserved copy. Rename a linked file outside Itacan, see a missing reference and explicitly relink. Other panes keep their content, sizes and focus.
6. Quit, move or copy the **closed** library, start offline from a fresh profile and choose the new location. Check actual Markdown bytes, image/PDF originals, task UUID and completion, daily Plan, Oath history, report evidence, Resource attachment, mixed preset and portable settings. Device paths and permissions can be set afresh. Use the recovered Project for the next work session.

### Closed-alpha release gate

After the internal run, allow an internal daily-use/polish period. Before inviting testers, require a versioned native installer/package for each platform actually offered, working offline without Node, visual identity and licensed artwork/fonts, any required signing/notarization, real native chooser, accessible first-run guidance and a tested restore procedure. Verify upgrade-in-place and uninstall/reinstall preserve the separately chosen library. Prefer a documented manual update from a signed release for the first cohort. An automatic network updater adds distribution infrastructure before it solves a first-cohort need. Platform packaging and update mechanisms differ. [Electron distribution and updates](https://www.electronjs.org/docs/latest/tutorial/updates)

Use tester-sized libraries on actual devices, repeat interruption/conflict tests, verify default shortcuts/keyboard layouts, input methods, media decoding, permissions, high DPI, trash, display restoration and basic accessibility. Offer concise help for external moves, backups, one active writer, Oath limits and recovery. Run the copy-first importer with representative consenting legacy users before offering migration to that cohort. Test a clean-install path separately for new users. Distribute Strict only on platforms where preflight, consent, recovery and the exact stated protections pass. Local audio and online integrations are optional and their absence cannot prevent offline start.

## Product discrepancies for the team review

The following design details have working defaults for implementation and acceptance. The team can refine them during internal use. Atlas outside Itacan, workspace-first quick capture with optional attachment, single-user offline use, interactive Athena deferral and the exclusion of Obsidian’s plugin ecosystem, graph, backlinks, canvas, command palette, YAML properties UI, wikilink tooling and user-authored CSS/themes are settled.

| Decision | Sources and what a researcher would experience | Recommendation and focused team question |
|---|---|---|
| Workspace Full view | `M/Functionality.md`, “Folders and subfolders”, describes one panel per top-level folder. `H/lib/ui/workspace-explorer.js` and `A/renderer/workspace/workspace.js` show a tree and a single Files surface next to Tasks and Progress. With many folders these allocate very different amounts of working space. | Retain the unified explorer and add attached Resource folders inside it. **Is this the intended Full-view composition for all workspaces?** |
| Saving while writing | `A/README.md`, “Editing”, and `A/renderer/document/document.js` expose explicit Save/Discard/Cancel. The earlier investigation’s “What needs to survive a crash” proposes short idle autosave. Automatic persistence changes the meaning of closing a draft and of undoing a saved edit. | Default to one-second idle autosave with visible Saving/Saved/Conflict, manual Save and a manual-mode preference. Undo remains available within the document session. **Should idle autosave be the initial preference?** |
| Regular Oath fulfilment | `M/The Oath Functionality.md`, “Agreed functionality”, specifies one chosen end condition. `H/lib/domain/oath.js`, `fulfilmentTime`, can fulfil when the timer or selected tasks finish and let the session continue. | Each Regular Oath fulfils once by its stated rule. Continued commitment starts a new record. **Should that explicit rule govern regardless of which event happens first?** |
| Scheduled Regular Oath | The same feature design treats cancellation on the scheduled day as Break. Hub’s `H/lib/services/oath.js`, `end`, permits ordinary cancellation before activation. This changes what appears in History on the morning of an afternoon session. | Adopt the design’s day boundary in the start timezone. If the app was closed, reconcile missed sessions on launch, avoid surprise locking and record that activation was missed. **Should same-day cancellation count as broken before the scheduled hour?** |
| Regular Oath protections | `M/Functionality.md`, “Notifications” and “Application and website restrictions”, promises outside suppression. The tested scope in `H/lib/domain/oath-strict.js`, `STRICT_TERMS`, explicitly allows OS controls and cannot guarantee suppression. | Offer Regular as a clearly described in-app commitment on supported desktops. **Does that accurately scoped Regular experience meet the product promise?** |

**Inferred — remaining feature defaults.** Use the existing Project/Resource ownership model for scoped tasks and let selected shared folders extend a Project’s context. Preserve daily/weekly recurrence. “Planned” affects the schedule, while “Due” orders actionable tasks. Retain individual Step state on parent completion and show unfinished Steps. For Regular Oaths, timed sessions keep their timer condition if all work finishes early. For scheduled task-based Oaths already satisfied at start, record fulfilment at the scheduled start without entering fullscreen. Additions to an active commitment are explicit. Removing required work requires ending or breaking it. During an intentional rest for an indefinite or task-based session, relax in-app navigation, visibly retain the commitment, pause credited time and resume on the stated deadline. Defer automatic idle deductions and camera presence until the time-accounting and privacy experience warrants them. These defaults close the feature designs’ remaining questions for the internal run.
